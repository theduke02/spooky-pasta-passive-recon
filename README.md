# Spooky Pasta – Passive OSINT Reconnaissance

## Project Overview

Spooky Pasta is a passive Open-Source Intelligence (OSINT) reconnaissance project focused on analyzing GitHub's publicly available attack surface without directly interacting with or attempting to exploit the target.

The project demonstrates how publicly accessible information can be collected, correlated, and analyzed to identify potential security exposures and provide evidence-based recommendations.

## Objective

The objective of this project was to perform non-intrusive reconnaissance against GitHub using publicly available information and demonstrate how cybersecurity professionals can use OSINT techniques during the reconnaissance phase of a security assessment.

## Tools & Technologies

* WHOIS
* DNS / nslookup
* dig
* MX and SPF record analysis
* crt.sh Certificate Transparency
* Netcraft
* Public web searches
* Kali Linux
* OSINT techniques

## Methodology

The project followed a passive reconnaissance methodology that included:

1. Domain and registration intelligence gathering
2. DNS infrastructure analysis
3. MX and email-security record analysis
4. SPF configuration review
5. Certificate Transparency analysis
6. Public subdomain and infrastructure discovery
7. Identification and documentation of publicly exposed information
8. Security-risk analysis and mitigation recommendations

## Key Findings

The investigation demonstrated how publicly available sources can reveal valuable information about an organization's external infrastructure, including domains, subdomains, DNS records, certificate information, email infrastructure, and other components of the public attack surface.

The collected intelligence was analyzed from a defensive cybersecurity perspective to identify potential areas of exposure and recommend appropriate mitigation measures.

## Ethical Considerations

This project was conducted for educational and cybersecurity training purposes. Reconnaissance activities were limited to passive collection and analysis of publicly available information. No exploitation, unauthorized access, credential testing, or intrusive scanning was performed against GitHub systems.
